2:T156d,<h1 id="architecture"><a class="heading-anchor" href="#architecture">Architecture</a></h1>
<p>BlackStory is a place-connected Black history research platform. Public surfaces
serve only released historical projections. Research, evidence, and promotion
stay behind private APIs, workers, and admin tools.</p>
<h2 id="current-stack-verified-2026-08-28"><a class="heading-anchor" href="#current-stack-verified-2026-08-28">Current stack (verified 2026-08-28)</a></h2>
<p>Checked against live <a href="https://blackstory.app/">blackstory.app</a> headers and CSP.
This is the current story. Older notes that still name Firebase App Hosting or
Firestore as the system of record are leftover.</p>

<p>The live homepage is a catalog filter board (Kind / Tone / Era / Theme / Status /
Confidence / Where), about 4,100 released records. The product line <em>History,
pinned to place</em> is the design target. It is not a claim that today's front door
already works as map-first story-finding.</p>
<p>This repository only configures Supabase project <code>blackstory-app</code>. Other org Pro
projects are not named in repo config, so unused is not proven here. Aligning
docs on Vercel + Supabase does not close overages or standing bills.</p>
<h2 id="surfaces"><a class="heading-anchor" href="#surfaces">Surfaces</a></h2>
<pre><code>apps/web                 Public Next.js on Vercel (live: blackstory.app)
apps/admin               Private admin / research console (separate Vercel project)
apps/api-public          Public read / search / location (in-repo; Cloud Run deploy unverified)
apps/api-submissions     Corrections / contribution intake (in-repo; Cloud Run deploy unverified)
apps/api-internal        Publication / promotion (in-repo; Cloud Run deploy unverified)
apps/mobile              Expo mobile app (isolated lockfile)
apps/docs                This GitHub Pages site
workers/*                Research, publication, security
packages/*               Shared libraries (@repo/*)
supabase/                Postgres migrations for blackstory-app
infra/*                  Leftover Firebase / GCP scaffolding, parked PostGIS
</code></pre>
<p>Do not add deployable microservices beyond this set. Historical decision text
is in git (<code>git log -- docs/adr/</code>).</p>
<h2 id="data-plane"><a class="heading-anchor" href="#data-plane">Data plane</a></h2>
<p><strong>Product system of record</strong> is Supabase Postgres (<code>blackstory-app</code>), with
schema and migrations under <code>supabase/migrations/</code> and
<code>docs/data/postgres-schema.md</code>.</p>
<p>Public and admin apps read with <code>PUBLIC_DATA_SOURCE=postgres</code> /
<code>ADMIN_DATA_SOURCE=postgres</code> and a server-only <code>DATABASE_URL</code>. Published
developer reads may use PostgREST views. Blobs: Supabase Storage for
<code>public-media</code>. GCS dual-serve and Firestore export tools are leftover
(<code>docs/data/firebase-wind-down.md</code>).</p>
<p>Local PostGIS under <code>infra/database/</code> is parked leftover scaffolding, not the
production path. Cloud SQL and SQL Connect are permanently non-path.</p>

<h2 id="product-constitution"><a class="heading-anchor" href="#product-constitution">Product constitution</a></h2>
<p>Shared policy lives in <code>packages/schemas/constitution/policy.v1.json</code>. TypeScript
loads it through <code>@repo/schemas</code>. Python workers load the same JSON through
<code>black_book_constitution</code>. Thresholds and living-person rules change by version
bump, not by an HTTP write API.</p>

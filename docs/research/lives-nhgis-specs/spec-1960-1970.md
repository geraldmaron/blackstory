# Lives Across the Decades — IPUMS NHGIS published-table spec, 1960 and 1970

**Scope:** decades 1960 and 1970, conditions `population_share`, `urban`, `homeownership`,
`high_school`, `unemployment`, `income`. Nation and state only.
**Method:** every dataset, table, variable and breakdown code below was returned by a live call to
`https://api.ipums.org/metadata/nhgis/...?version=2` on 2026-09-15. Nothing here is inferred from a
naming pattern. Where the API does not answer a question, the section says so instead of guessing.
**Shape reference:** `packages/ops-data/src/lives/decennial.ts`
(`LIVES_DECENNIAL_DATASETS` / `LIVES_DECENNIAL_TABLES`).

`1960_cPop` and `1960_cAge1` return **no `breakdowns` key at all**. 1960 has no geographic-component
(urban) and no race breakdown mechanism in NHGIS; 1960 race lives inside variable descriptions only.

`1970_Cnt1` likewise returns **no `breakdowns` key** — its extract entry takes `breakdownValues: []`.

`1970_Cnt4Pa` is allocation/quality control (NT100–NT127: substitutions, allocations, unweighted
sample counts). It carries no usable condition table for this timeline. Not used below.

### The 1970 race/ethnicity breakdown, in full (`1970_Cnt4Pb`, breakdown `bs02`)

```
name: bs02
type: Race/Ethnicity
description: Race/Ethnicity (1970 Census Population & Housing)
breakdownValues:
  bs02.ch000  All races
  bs02.ch001  White
  bs02.ch004  Black
  bs02.ch235  Spanish American (Hispanic)
```

This is the analog of 1980's `bs04.ch*` and 1990's `bs10.ch*`. An extract of `1970_Cnt4Pb` must name
these values explicitly, exactly as `LIVES_DECENNIAL_DATASETS['1980_STF2b'].breakdownValues` names
`bs04.ch00` etc.

### The 1970 spatial breakdown, relevant values

`1970_Cnt2` breakdown `bs01` — "Geographic Subarea (1970 Census Population & Housing)", 15 values.
The two this timeline needs:

```
bs01.ge000  Total area
bs01.ge001  Urban
```

(the rest of `bs01` on Cnt2: `ge012` urbanized-area central place, `ge020` urban fringe, `ge032`
urban places 2,500–9,999 outside urbanized areas, `ge029` urban places 10,000+ outside urbanized
areas, `ge045` Rural, `ge049` rural places 1,000–2,499, `ge052` rural not in place of 1,000+,
`ge070`/`ge086`/`ge089`/`ge113` MSA/CMSA splits, `ge093`/`ge098` non-MSA splits.)

`1970_Cnt4Pb` and `1970_Cnt4H` carry their own `bs01` with 20 values. Same two codes,
same descriptions: `bs01.ge000` "Total area", `bs01.ge001` "Urban". Their rural is split
farm/nonfarm (`ge053` "Rural--farm", `ge046` "Rural--nonfarm") rather than Cnt2's single `ge045`.

- **universe (exact):** `Persons`
- **description:** `Sex by Race`
- **geogLevels confirmed:** `nation`, `state` (also `county`)
- **breakdownValues required:** none — dataset has no breakdowns
- **variables (exact codes and description strings):**

| code | description |
|---|---|
| `B5S001` | `Male >> White` |
| `B5S002` | `Male >> Negro` |
| `B5S003` | `Male >> Indian` |
| `B5S004` | `Male >> Japanese` |
| `B5S005` | `Male >> Chinese` |
| `B5S006` | `Male >> Filipino` |
| `B5S007` | `Male >> Other races` |
| `B5S008` | `Female >> White` |
| `B5S009` | `Female >> Negro` |
| `B5S010` | `Female >> Indian` |
| `B5S011` | `Female >> Japanese` |
| `B5S012` | `Female >> Chinese` |
| `B5S013` | `Female >> Filipino` |
| `B5S014` | `Female >> Other races` |

- **group cells:** Black = `B5S002 + B5S009` (label text **`Negro`**). White = `B5S001 + B5S008`
  (label text **`White`**; in 1960 this white total includes people later counted as Hispanic).
- **denominator / base:** either the sum of all 14 `B5S*` cells, or the separate table
  `1960_cPop NT1`, prefix **`B5O`**, universe `Persons`, description `Total Population`,
  single variable `B5O001` = `Total`.

- **definitional trap:** this table crosses **Negro**, not Nonwhite. It publishes seven named race
  categories; `Other races` is a residual, not a nonwhite total. If the ingest ever needs the
  nonwhite concept it must come from a different table (below) and be labeled as a different concept.

### 1960 — the Nonwhite concept, published separately (do not conflate)

- **dataset:** `1960_cAge1` — "1960 Census | Detailed Age Data for All Ages [US, States & Counties]"
- **table:** `NT10`, nhgisCode prefix **`B48`**
- **universe (exact):** `Persons`
- **description:** `Race`
- **geogLevels confirmed:** `nation`, `state`, `county`
- **variables:** `B48001` = `White`; `B48002` = `Non-white`

Companion tables crossing the same two-way split: `1960_cAge1 NT13` prefix `B5B`
(`Race by Sex`, universe `Persons`: `B5B001 White >> Male`, `B5B002 White >> Female`,
`B5B003 Non-white >> Male`, `B5B004 Non-white >> Female`) and `1960_cAge1 NT8` prefix `B5I`
(`Race by Age`, universe `Persons`, 36 cells: `White >> 0 to 4 years of age` …
`Non-white >> 85 years of age and over`).

Also published and easy to misread: `1960_cPop NT14`, prefix **`B5T`**, description
`Nonwhite Population 21 Years of Age and Over by Sex`, universe **`Non-White Persons 21 Years and
Over`** (`B5T001` = `Male`, `B5T002` = `Female`) — a **Nonwhite 21+** count, not a Negro count and
not a 25+ base. And `1960_cPop NT15`, prefix **`B5U`**, description `Total White Population`,
universe `White Persons`, `B5U001` = `Total`.

**`Non-white` ≠ `Negro`.** In 1960 the nonwhite total carries Indian, Japanese, Chinese, Filipino
and other races on top of the Negro population. A figure from `B48` must be sliced and labeled
`nonwhite`, never `black`.

- **description:** `Sex by Race`
- **geogLevels confirmed:** `nation`, `region`, `division`, `state`, `county`, `tract`, … — nation and state both present
- **breakdownValues required:** `bs01.ge000` (`Total area`) for the population count
- **variables:**

| code | description | | code | description |
|---|---|---|---|---|
| `CEB001` | `Male >> White` | | `CEB010` | `Female >> White` |
| `CEB002` | `Male >> Negro` | | `CEB011` | `Female >> Negro` |
| `CEB003` | `Male >> Indian` | | `CEB012` | `Female >> Indian` |
| `CEB004` | `Male >> Japanese` | | `CEB013` | `Female >> Japanese` |
| `CEB005` | `Male >> Chinese` | | `CEB014` | `Female >> Chinese` |
| `CEB006` | `Male >> Filipino` | | `CEB015` | `Female >> Filipino` |
| `CEB007` | `Male >> Hawaiian` | | `CEB016` | `Female >> Hawaiian` |
| `CEB008` | `Male >> Korean` | | `CEB017` | `Female >> Korean` |
| `CEB009` | `Male >> Other` | | `CEB018` | `Female >> Other` |

- **group cells:** Black = `CEB002 + CEB011`, race label text **`Negro`**.
  White = `CEB001 + CEB010`, label text **`White`** (includes Hispanic white people in 1970).
- **denominator / base (everyone):** sum of all 18 `CEB*` cells at `bs01.ge000`.
  Cross-check available: `1970_Cnt1 NT1`, prefix **`CBC`**, universe `Persons`,
  description `All Persons`, `CBC001` = `Total`.
- **alternate race total, 100-percent, no breakdowns:** `1970_Cnt1 NT20`, prefix **`CBW`**,
  universe `Persons`, description `Race` — `CBW001 White`, `CBW002 Negro`, `CBW003 Indian`,
  `CBW004 Other non-specified races`, `CBW005 Reported "other race"`. Five cells, not nine;
  use it only as a cross-check, not as the same series as `CEB`.

### Path B — Hispanic (and a like-for-like Black/white sample denominator)

- **dataset:** `1970_Cnt4Pb` — "1970 Census | Count 4Pb - Sample-Based Population Data with Race/Ethnicity Breakdown"
- **table:** `NT17`, nhgisCode prefix **`C1U`**
- **universe (exact):** `Persons`
- **description:** `Sex by Age`
- **geogLevels confirmed:** `nation`, `region`, `division`, `state`, `county`, … — nation and state both present
- **breakdownValues required:**
  - everyone: `bs01.ge000` × `bs02.ch000` (`Total area` × `All races`)
  - white: `bs01.ge000` × `bs02.ch001` (`White`)
  - Black: `bs01.ge000` × `bs02.ch004` (`Black`)
  - Hispanic: `bs01.ge000` × `bs02.ch235` (`Spanish American (Hispanic)`)
- **variables:** 54 cells, `C1U001` = `Male >> Under 3` through `C1U027` = `Male >> 75 and over`,
  `C1U028` = `Female >> Under 3` through `C1U054` = `Female >> 75 and over`. The group total is the
  sum of all 54 within its breakdown; the base is the same sum at `bs02.ch000`.
- **simpler alternative with the same universe:** `1970_Cnt4Pb NT18`, prefix **`C1V`**,
  universe `Persons`, description `Household Relationship and Sex`, 12 cells
  (`C1V001 Male primary individual` … `C1V012 Female in other group quarters`) — also sums to the
  group's total persons and is 12 cells instead of 54.
- **definitional trap — the Spanish-origin universes:** NHGIS's breakdown label is literally
  `Spanish American (Hispanic)` and the API gives no composition for it. **Do not blur it with the
  four separately published Spanish concepts**, which the same dataset publishes as a single table:

  - **dataset:** `1970_Cnt4Pb`, **table:** `NT24`, nhgisCode prefix **`C11`**
  - **universe (exact):** `Persons`
  - **description:** `Spanish Indicator`
  - **variables (exact):**

  | code | description |
  |---|---|
  | `C11001` | `Any of five Spanish categories of the question on "origin or descent"` |
  | `C11002` | `Puerto-Rican birth or parentage` |
  | `C11003` | `Spanish language` |
  | `C11004` | `Not of "Spanish language" but of Spanish surname (in 5 Southwestern states only)` |

  These are four different universes with four different counts. `C11004` is by its own published
  wording **five states only**, so it cannot carry a national or all-state Hispanic series.
  `C11001` is the origin-or-descent question, which in 1970 was asked on a sample form only.
  **Open item before ingest:** NHGIS's metadata API does not state which of these `bs02.ch235`
  is built from, and 1970 published "Spanish American" with a definition that varied by state
  group. Resolve it against the 1970 Census Users' Guide, Parts I & II
  (<https://assets.nhgis.org/original-data/modern-census/1970CNT1-4.pdf>), which NHGIS links from
  <https://www.nhgis.org/documentation/tabular-data>, and record the resolved definition in
  provenance before publishing any 1970 Hispanic figure. I did not open that PDF, so this spec
  does not assert a definition for `bs02.ch235`.

## 1970 — urban  ✅ VERIFIED (two paths, matching the two above)

### Path A — Black and white, 100-percent count

- **dataset:** `1970_Cnt2`
- **table:** `NT1`, prefix **`CEB`**, universe `Persons`, description `Sex by Race` (same table as above)
- **geogLevels confirmed:** `nation`, `state`
- **breakdownValues required:** numerator `bs01.ge001` (`Urban`); denominator `bs01.ge000` (`Total area`)
- **variables:** the same `CEB001`–`CEB018` list, read once under each breakdown value.
  Black urban share = (`CEB002 + CEB011` at `bs01.ge001`) / (`CEB002 + CEB011` at `bs01.ge000`).
- This is exactly the 1980 `NTB1` / 1990 `NPB1` "Total area" vs "Urban" pattern `decennial.ts`
  already implements via its `COMPONENTS` constant.

### Path B — Hispanic

- **dataset:** `1970_Cnt4Pb`
- **table:** `NT17` prefix **`C1U`** (or `NT18` prefix **`C1V`**), universe `Persons`
- **geogLevels confirmed:** `nation`, `state`
- **breakdownValues required:** `bs01.ge001 × bs02.ch235` over `bs01.ge000 × bs02.ch235`;
  same for `bs02.ch004` (Black) and `bs02.ch001` (White) if a single-source sample series is wanted
- **definitional trap — the urban definition:** 1970's `Urban` (`bs01.ge001`) is the post-1950
  definition (urbanized areas plus places of 2,500+), and Cnt2's rural residual is a single
  `Rural` value while Cnt4Pb/Cnt4H split rural into farm and nonfarm. The two datasets therefore
  do not partition identically below the urban line; only the `Urban` / `Total area` pair is
  comparable across them. Do not mix a Cnt2 numerator with a Cnt4Pb denominator.

## 1970 — homeownership  ✅ VERIFIED (100-percent for Black/white; sample for Hispanic)

### Path A — all, white, Negro, 100-percent count

- **dataset:** `1970_Cnt1` — "Count 1 - 100% Data [Block Groups, Enum. Districts, Cong. Districts, etc.]"
- **geogLevels confirmed:** `nation`, `region`, `division`, `state`, `county`, …
- **breakdownValues required:** none — `1970_Cnt1` has no `breakdowns`

| table | prefix | universe (exact) | description | variables |
|---|---|---|---|---|
| `NT26A1` | `CB4` | `Occupied Housing Units` | `Tenure` | `CB4001` = `Owner occupied`; `CB4002` = `Renter occupied` |
| `NT26A2` | `CB5` | `White Householders in Occupied Housing Units` | `Tenure` | `CB5001` = `Owner occupied`; `CB5002` = `Renter occupied` |
| `NT26A3` | `CB6` | `Negro Occupied Housing Units` | `Tenure` | `CB6001` = `Owner occupied`; `CB6002` = `Renter occupied` |

- **group cells:** Black homeownership = `CB6001 / (CB6001 + CB6002)`;
  white = `CB5001 / (CB5001 + CB5002)`; everyone = `CB4001 / (CB4001 + CB4002)`.
- **race concept:** the race is in the **universe string**, not a breakdown and not a cell label —
  `White Householders in Occupied Housing Units` and `Negro Occupied Housing Units`.
  These are one-universe-per-table tables, the 2000 `NH015I` / `NH015F` shape in `decennial.ts`
  (`groups: [{ slice: 'white' }]` with no `race`/`breakdown`/`cells`), not the 1980/1990
  breakdown shape.
- **definitional trap:** the white universe is worded as **householders** while the Negro universe
  is worded as **occupied housing units**. Both are counts of occupied units; the wording differs
  because NHGIS transcribed the published headers. Note it in provenance rather than normalizing.
  1970 "White" householders include Hispanic householders.

| `NT37F` | `CVG` | `Spanish American Occupied Units` | `Tenure by Number of Persons in Unit` |

| code | description | | code | description |

| `CVG002` | `Owner-occupied >> 2 persons in unit` | | `CVG011` | `Renter-occupied >> 2 persons in unit` |
| `CVG003` | `Owner-occupied >> 3 persons in unit` | | `CVG012` | `Renter-occupied >> 3 persons in unit` |
| `CVG004` | `Owner-occupied >> 4 persons in unit` | | `CVG013` | `Renter-occupied >> 4 persons in unit` |
| `CVG005` | `Owner-occupied >> 5 persons in unit` | | `CVG014` | `Renter-occupied >> 5 persons in unit` |
| `CVG006` | `Owner-occupied >> 6 persons in unit` | | `CVG015` | `Renter-occupied >> 6 persons in unit` |
| `CVG007` | `Owner-occupied >> 7 persons in unit` | | `CVG016` | `Renter-occupied >> 7 persons in unit` |
| `CVG008` | `Owner-occupied >> 8 persons in unit` | | `CVG017` | `Renter-occupied >> 8 persons in unit` |
| `CVG009` | `Owner-occupied >> 9 persons or more in unit` | | `CVG018` | `Renter-occupied >> 9 persons or more in unit` |

`CVC001`–`CVC018` (all occupied units) and `CVE001`–`CVE018` (Negro occupied units) carry the same
18 description strings. Owner share = sum of the nine `Owner-occupied >> …` cells over all 18.

- **definitional trap:** `1970_Cnt4H` publishes **no White universe at all** (zero tables in the
  dataset have "White" in the universe string). A Cnt4H Hispanic figure therefore has no
  same-dataset white comparator; the white comparator must come from `1970_Cnt1 NT26A2` (`CB5`),
  which is 100-percent rather than sample. Say so on the surface rather than presenting the two
  as one series.
- **cleanest total-only alternative:** `1970_Cnt4H NT36`, prefix **`CVA`**, universe `Occupied
  Units`, description `Tenure of Occupied Units` — `CVA001` `Owned or being bought (excludes
  cooperative or condominium units)`, `CVA002` `Cooperative or condominium units which are owned
  or being bought`, `CVA003` `Rented for cash rent`, `CVA004` `Rented units occupied without
  payment of cash rent`. No race variant exists for `NT36`.
- **tenure-cell trap for the existing parser:** `decennial.ts`'s `tenure` branch takes
  `cell.text.split(': ')[0]` and requires every selected cell to be owner or renter. The Cnt4H
  cells are `>>`-joined (`Owner-occupied >> 3 persons in unit`), not `: `-joined, and the four-way
  `1970_Cnt2 NT31*` cells are worded `Owned or being bought …` / `Rented for cash rent` /
  `Rented units occupied without payment of cash rent`. Neither matches the current
  `'owner occupied'` / `'renter occupied'` normalization. `1970_Cnt1 NT26A*` **does** match it
  exactly (`Owner occupied` / `Renter occupied`).
- **100-percent four-way tenure, also available, with an urban breakdown:** `1970_Cnt2`
  `NT31A` prefix `CFA` universe `Occupied Units`, `NT31B` prefix `CFB` universe `White Occupied
  Units`, `NT31C` prefix `CFC` universe `Negro Occupied Units`, all description `Tenure`, each
  with `…001 Owned or being bought (excludes cooperative and condominium units except when there
  are less than five such units in the tabulation area)`, `…002 Cooperative or condominium units
  which are owned or being bought`, `…003 Rented for cash rent`, `…004 Rented units occupied
  without payment of cash rent`. No Spanish universe.

### 1970 sample-base trap (applies to every `1970_Cnt4Pb` and `1970_Cnt4H` figure above)

1970 ran two sample questionnaires. Some items were collected on the 15-percent sample and some on
the 5-percent sample, and the published Count 4 tables therefore rest on different sample bases
depending on the subject — schooling, labor force and income items do not all share one base, and
the origin-or-descent question behind the Spanish-origin tabulations was a 5-percent item. NHGIS's
metadata API exposes no per-table sample-base field, so this spec cannot state which base each
table carries. Resolve per table against the 1970 Census Users' Guide, Parts I & II
(<https://assets.nhgis.org/original-data/modern-census/1970CNT1-4.pdf>) and record it in
provenance. Decennial sample tables carry no margins, so the project's existing rule applies:
withhold a region figure whose base is under 500 counted persons or households.

### One more 1970-wide trap worth recording

NHGIS's breakdown label is `Black` (`bs02.ch004`) while the variable descriptions inside the
100-percent tables (`CEB002`, `CBW002`, `CB6*`, `CFC*`) say `Negro`, which is what 1970 published.
The ingest matches on description text, so the two spellings live side by side in one decade.
Label the decade's group as the census did — **Negro** — and note that NHGIS relabeled the
breakdown.
